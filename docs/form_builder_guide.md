# フォームビルダー使い方ガイド

システム定義画面でJSONを直接入力する代わりに、GUIフォームで簡単に設定できます。

## マッピング定義フォームビルダー

### 基本設定
- **ファイルエンコーディング**: UTF-8 / Shift-JIS / CP932 から選択
- **区切り文字**: カンマ / タブ / セミコロン / パイプ / カスタム
  - カンマ (,): 標準的なCSV
  - タブ (\t): TSV（タブ区切り）
  - セミコロン (;): ヨーロッパ圏のCSV
  - パイプ (|): データベースエクスポート形式
  - カスタム: 任意の文字列（例: `::`, `||`）
- **クォート文字**: ダブルクォート / シングルクォート / なし
  - ダブルクォート ("): `"値",` のように囲まれた文字列
  - シングルクォート ('): `'値',` のように囲まれた文字列
  - なし: クォートなしのファイル
- **ヘッダー行あり**: CSVファイルの1行目がヘッダーかどうか
  - ✓ あり → **元カラム名**を入力
  - □ なし → **列番号**を入力
- **スキップ行数**: ファイルの先頭から読み飛ばす行数

### カラム定義テーブル

| 項目 | 説明 | 例 |
|-----|------|-----|
| **元カラム名** | CSVファイルのヘッダー名（ヘッダー行あり時） | `ユーザーID` |
| **列番号** | CSVファイルの列番号（0始まり、ヘッダー行なし時） | `0` |
| **DBカラム名** | データベースのカラム名（必須、大文字） | `USER_CD` |
| **データ型** | string / number / date | `string` |
| **必須** | 必須項目かどうか | ✓ |
| **トリム** | 前後の空白を削除 | ✓ |
| **変換** | 小文字/大文字変換 | `小文字` |

### 使い方

1. **「+ 列を追加」ボタン**で行を追加
2. 各項目を入力
3. **「削除」ボタン**で不要な行を削除
4. **「JSON直接入力」タブ**でJSON形式も確認可能
5. **「保存」ボタン**で自動的にJSONに変換して保存

### 注意事項

- **USER_CD は必須**: 在籍マスタとの紐付けに使用
- **元カラム名 と 列番号の使い分け**:
  - **ヘッダー行あり**: `元カラム名`を入力（推奨）
  - **ヘッダー行なし**: `列番号`を入力（0始まり）
  - 両方入力も可能（列番号が優先される）
- **DBカラム名**: 必ず大文字で入力（例: `USER_CD`, `USER_NAME`）
- **背景色**: グレー背景のフィールドは現在の設定では使用されません

## 出力項目定義フォームビルダー

### カラム定義テーブル

| 項目 | 説明 | 例 |
|-----|------|-----|
| **DBカラム名** | データベースのカラム名（大文字） | `USER_CD` |
| **表示名** | スプレッドシートに表示する名前 | `ユーザーID` |
| **順序** | 表示順序 | `1` |
| **幅** | 列の幅 | `15` |
| **フォーマット** | text / number / date | `text` |

### 使い方

1. **「+ 列を追加」ボタン**で行を追加
2. 各項目を入力
3. **「削除」ボタン**で不要な行を削除
4. **「JSON直接入力」タブ**でJSON形式も確認可能
5. **「保存」ボタン**で自動的にJSONに変換して保存

## タブの使い分け

### フォーム入力タブ（推奨）
- 初心者向け
- 項目ごとに入力
- 入力ミスが少ない
- 視覚的にわかりやすい

### JSON直接入力タブ
- 上級者向け
- 既存のJSONをコピー＆ペースト
- 一括編集が可能
- フォーマットエラーに注意

## サンプル設定例

### 例1: SAP人事システム

**マッピング定義**（ヘッダー行あり）:
```
元カラム名: ユーザーID → DBカラム名: USER_CD (必須、トリム)
元カラム名: 氏名 → DBカラム名: USER_NAME (必須、トリム)
元カラム名: 所属コード → DBカラム名: DEPARTMENT_CD (トリム)
元カラム名: 所属名 → DBカラム名: DEPARTMENT_NAME (トリム)
元カラム名: メールアドレス → DBカラム名: EMAIL (トリム、小文字変換)
```

**マッピング定義**（ヘッダー行なし）:
```
列番号: 0 → DBカラム名: USER_CD (必須、トリム)
列番号: 1 → DBカラム名: USER_NAME (必須、トリム)
列番号: 2 → DBカラム名: DEPARTMENT_CD (トリム)
列番号: 3 → DBカラム名: DEPARTMENT_NAME (トリム)
列番号: 4 → DBカラム名: EMAIL (トリム、小文字変換)
```

**出力項目定義**:
```
USER_CD → ユーザーID (順序:1, 幅:15)
USER_NAME → 氏名 (順序:2, 幅:20)
DEPARTMENT_CD → 所属コード (順序:3, 幅:12)
DEPARTMENT_NAME → 所属名 (順序:4, 幅:30)
EMAIL → メールアドレス (順序:5, 幅:30)
```

### 例2: Active Directory

**マッピング定義**:
```
元カラム名: samAccountName → DBカラム名: USER_CD (必須、トリム)
元カラム名: displayName → DBカラム名: USER_NAME (必須、トリム)
元カラム名: department → DBカラム名: DEPARTMENT_NAME (トリム)
元カラム名: mail → DBカラム名: EMAIL (トリム、小文字変換)
元カラム名: enabled → DBカラム名: ACCOUNT_STATUS (トリム)
```

## トラブルシューティング

### エラー: JSONが不正です

**原因**: フォーム入力に不備がある
**解決策**:
1. **DBカラム名**が空の行を削除
2. **必須項目**（USER_CD）が設定されているか確認
3. **JSON直接入力タブ**でエラー内容を確認

### データ取り込み時にエラー

**原因**: CSVファイルとマッピング定義が一致していない
**解決策**:
1. CSVファイルのヘッダー行を確認
2. **元カラム名**がCSVと完全一致しているか確認
3. **列番号**が正しいか確認（0始まり）

### 保存後にテーブルエラー

**原因**: マッピング定義を変更するとテーブルが再作成される
**解決策**:
1. データを再度取り込む必要があります
2. 既存データは削除されます（注意）
